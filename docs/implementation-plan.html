01 File number and column widths

The file number showed as BL/ENOTES/GL/PAT/AN/LAPTOP… — cut at 30 characters. It was never a column-width problem, which is why widening the column had no effect.

Cause
A 30-character limit compiled into the product's own Java, applied before the page is drawn. No stylesheet or column setting can reach it.
Fix
One setting in webdesktop.ini (EnableWordWrapForQVar) lifts the limit; a small stylesheet addition keeps the full value on one line, capped at 320px so a single long entry cannot stretch the grid.
Also done
Columns can now be dragged to resize, with double-click to fit the content. Widths last for the session — the product has nowhere to store them per user.

02 Colour by work-item state

Rows are now tinted by state: amber for not started, blue for running, green for completed, with a coloured bar down the left edge.

Cause
Not a defect — the feature does not exist. The product colours rows from a queue variable, and work-item state is not one, so no configuration can express it. Colouring by stage was tried and abandoned: a stage says where an item sits in the process, not whether it has started, so every row came out the same colour.
Fix
A short script reads the state already shown in the grid and tints the row. It queries nothing and adds nothing to the page.
Limits
A view that does not display the Workitem State column stays uncoloured — Sent Items shows Stage instead. Completed items rarely appear at all, because finished work leaves the queue.
Decision
Confirm which column and values should drive the colours. Retargeting it is a two-line edit, so this is a question for the client, not more development.

03 Tile appearance

The four count tiles were flat colour blocks with a dead white strip above each. They now read as cards: the colour fills the tile, the title sits on it, the icon is in a round chip, the count sits under its label, with a rounded edge and a hover lift.

Route
Stylesheet only — no scripts, nothing replaced. Two applications are involved because one tile is a panel from one drawn inside a frame from the other.
Config
Colours, icons and the heading are set per tile in Business Admin → Criteria Management → Criteria Visualization. The missing heading on My Inbox was one checkbox there, now enabled.
Ceiling
Font sizes are configurable, but only as Small, Medium or Large — 10, 12 and 15px. The count already sits at the 15px maximum, so configuration can only shrink the label, and both smaller sizes tested worse. A prominent headline number needs one line of stylesheet, which scales whatever size is configured rather than replacing it.
Not possible
Equal tile widths. The dashboard places every panel itself, at fixed positions on a 12-column grid; changing a width in the stylesheet resizes one tile without moving the next, so they overlap. The row is full — the navigation bar takes 2 columns and the four tiles take the remaining 10, which does not divide into four. Equal tiles need either a fifth panel in the row or a wider navigation bar, both layout configuration.
Why not code it
It is technically possible but not safe or maintainable: it would mean overriding the dashboard's layout engine on every render — on load, on resize, on refresh, on any rearrangement — with overlapping tiles as the failure mode rather than an untidy one. Equal widths belong in the layout configuration.

Two rules that govern all of this

  • Configuration is shared and immediate. Colours, fonts, icons and headings live in the central database, so a change is live for every user at once. There is no separate test copy — our machine reads the same database.
  • Stylesheet and script changes sit inside the product's own files. Each is appended, marked with a comment, and removed by deleting that block. They must be re-applied after any upgrade or redeployment of the product.

Open decisions

  1. Which field drives the row colours — client to confirm; two-line change once known.
  2. Equal tile widths — needs a layout change: add a fifth panel, or widen the navigation bar. Neither is safe to do from code.

Handing it over

Each item has its own folder with the files and a short set of steps — append the given block, redeploy, restart. Every change is append-only and reversible, and nothing in the product's own code is edited in place.
